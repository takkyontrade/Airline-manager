# 航空会社運営ゲーム（仮）

1960年の日本で航空会社を立ち上げ、実際の航空史に沿って経営していく、ブラウザで遊ぶ1人用のターン制経営シミュレーションです。

仕様書: https://claude.ai/artifact/Gqra1eGitTu53mLP3ErsPx

## 遊び方（手元で動かす）

Node.js 20 以上が必要です。

```
npm install
npm run dev
```

表示されたURL（例: http://localhost:5173）をブラウザで開きます。

## 今できること（第1段階）

- 会社名と拠点空港を決めて1960年1月からスタート（資本金5億円）
- 日本地図で空港を2つクリックして路線を開設
- 機材市場で新造機・中古機を購入またはリース
- 路線ごとに運賃と週の便数を設定し、機体を割り当て
- 「1か月進める」で需要・旅客数・収支を計算（燃料費・整備費・人件費・空港使用料・リース料など）
- 資金がマイナスのまま3か月続くと倒産
- ブラウザへの自動保存と、ファイルへの書き出し・読み込み

## 第2段階で追加したこと

- 新造機の発注（機種ごとの納期、手付金20%・残金は納入時）
- リース3種類：オペレーティング（3〜12年）、ファイナンス（10年で自社のものに）、ウェット（乗員・整備込みの短期）
- 毎月入れ替わる中古機市場（機齢・状態・飛行時間つき）
- 銀行借入（時代ごとの金利、担保と利益で借入枠が決まる）と一括返済
- 機種ごとのパイロット資格：経験者採用（毎月の上限あり）、新人訓練・移行訓練（4か月）。足りないと飛べない
- 整備の方針（節約・標準・手厚い）、機体の状態と経年劣化（燃費・快適さに影響）
- 飛行5,000時間ごとの重整備（Cチェック1か月、3回に1回はDチェック2か月）、期限切れは飛行停止

## 第3段階で追加したこと

- 機体ごとの1日のダイヤ（曜日指定つき）。路線ごとに「週の目標便数・使う機種・ダイヤの方針」を決めると自動で組む
- 方針：詰めて組む／一日に均等／朝夕を厚く／ハブで乗り継ぎ（運航計画部門の規模で使えるものが増える）
- ダイヤ画面で機体ごとのタイムラインを確認し、手動で便の追加・時刻変更・削除。手で直した機体は「固定」
- 折り返しの余裕時間の設定。遅延はその日の後の便に連鎖し、空港の運用時間を過ぎると欠航
- 定時率が評判と旅客の選択に影響。混雑空港・冬の雪・夏の台風で遅れやすい
- 空港の運用時間（門限）と、羽田・伊丹の発着枠（毎年4月に追加配分）
- 乗員基地：機体の拠点が基地でないとホテル代がかかる
- 出発時刻の人気（朝夕は高く、昼や深夜は低い）

## 第4段階で追加したこと

- 架空のライバル会社（ナショナルフラッグ・大手・ローカル線・沖縄・新規参入・LCC）が時代に合わせて路線を飛び、旅客を奪い合う
- あなたが大きなシェアを取ると、ライバルは便を増やし運賃を下げて対抗
- 時代のルール：2000年まで路線は免許制（幹線への参入には評判と機材の実績が必要、ローカル線は自由）。運賃は1995年まで認可制、1999年まで幅運賃
- 新幹線の開業で並行する航空需要が減る。五輪・万博は需要増、オイルショック・震災・リーマン・ショックなどは需要減
- 空港の開港・閉港（成田・関西・中部の開港、小牧の国内線終了で拠点の自動移転）と滑走路の延長
- DC-10・787の運航停止、ライバル会社の合併や破綻などのニュース
- 機種を約60種類に拡充（アイランダーから747-400、777-300ER、787-10、A350-1000まで）
- 「ライバル・規制」画面で各社の路線網と今のルールを確認

## 第5段階で追加したこと

- 日本発の国際線：アジア・太平洋・北米・欧州など約35の海外空港（ソウルは金浦から仁川へ、台北は松山から桃園へなど、時代で使える空港が変わる）
- 1986年までは国際線は日本国際航空の独占。以降は評判と機材の実績で参入できる。羽田は1978〜2009年は国際線なし（成田のみ）、伊丹は関空開港まで
- 国際線の運賃はドル建ての相場が基準で、為替（プラザ合意後の円高など）で円での売上が変わる。海外の空港使用料もドル建て
- ETOPS：双発機の洋上飛行は1985年から段階的に解禁（767は120分→180分、777や787はさらに長く）。4発機・3発機は制限なし
- 長距離便は日付をまたぐダイヤを自動で組む（例：成田〜ニューヨークは2日で1往復）。海外での乗員の宿泊費もかかる
- 乗り継ぎ需要：自社の国内線とゲートウェイ空港の国際線をつなぐと、地方からの乗り継ぎ客が増える（「ハブで乗り継ぎ」方針でさらに増加）
- 海外の架空ライバル会社（各国1社）。コードシェア（1990年〜、3社まで）と3つの架空アライアンス（1997年〜）。各連合に入れる日本の会社は1社だけ
- 地図に「日本／アジア／世界」の切り替え
- 国内線の需要モデルを調整（地方どうしの路線は小さく、羽田〜地方の幹線は大きく）。1960年の新興会社はローカル線から始めて、3機・評判50で幹線に参入できる

## 第6段階で追加したこと

- 貨物：旅客便の床下で貨物を運ぶ（国際線は日本発の輸出貨物で大きい）。地図右上で「貨物路線を開設」に切り替えると貨物専用路線を作れる（貨物機だけが飛ぶ）。運賃は円/kgで設定
- 貨物機：新造の貨物型（DC-8F、747-200F、MD-11F、747-400F、767-300F、777F、747-8Fなど）
- 旅客機→貨物機の改修：実在した改修プログラムだけ（727-200F、A300B4F、747-200SF、747-400BCF、767-300BCF、A330-300P2F、737-800BCF、777-300ERSF など）。始まった年から、機齢8年以上の自社保有機を4か月かけて改修。パイロットの型式資格はそのまま
- 安全：機体の状態（整備の方針）・機齢・機種の多さ・運航計画部門の規模で、軽微なトラブル・重大インシデント・機体を失う重大事故の起きやすさが変わる。ゼロにはならない
- 重大事故は評判の大幅低下と、数か月の客離れ。重大インシデントは修理で運休。航空保険料はリスクに応じて上下
- 「人員・整備」画面に事故リスク（業界平均の何倍か）と安全記録

## 第7段階で追加したこと

- 座席クラス：路線ごとに「エコノミーのみ／2クラス／3クラス」。上級席は場所を取るが運賃の何倍も稼げる。初めて導入してから数年かけて浸透し（評判が高いほど早い）、1979年より前は浸透に限界がある
- ファンサービス（「ブランド」画面）：機体見学会、特別塗装、復刻塗装（創業20年から）、引退が近い機種のフェアウェルフライト。評判が上がり、特別塗装機が飛ぶ路線は少し選ばれやすい
- 塗装とロゴのエディタ：胴体・ライン・尾翼の色と尾翼の文字。機材一覧やオペレーションルームの機体の絵に反映
- オペレーションルーム表示：ヘッダーで地図と切り替え。出発便の一覧、主要な数字、全機の状態
- セーブ枠3つ（自動保存とファイル書き出しに加えて）

## その後の改善

- 周回ルート（三角運航など）：路線タブで3〜4空港を選ぶと、1機が A→B→C→A と回って拠点に戻るダイヤを自動で組む。足りない区間の路線は自動で開設（国内線のみ）
- GitHubに保存：ヘッダーの「GitHub保存」から、自分のGitHubの非公開Gistに会社名ごとにセーブ・読み込みできる（Gist書き込み権限のトークンが必要。トークンはブラウザ内にだけ保存）
- 発着枠を現実寄りに：羽田・伊丹・成田の枠は滑走路の供用などでまとめて増え（1964・1978・1988・1997・2000・2010・2013年など）、国の評価（評判・地方路線網・安全性・枠の使用率）で配分。1997年からは新規参入枠、2005年からは5年ごとに未使用枠を回収
- 給油のための経由地（アンカレッジ・ホノルル・グアム）。航続距離が足りない機体でも飛べるが、時間がかかり直行便より選ばれにくい
- 冷戦期はソ連上空を避けて欧州線が遠回り（1970年まで1.35倍、1991年まで1.15倍の距離）。1960年代のDC-8で欧州へはアンカレッジ経由
- 長距離便のダイヤを手で編集（日付をまたぐ時刻、何日で1往復か）
- 始める年（1960・1972・1986・2000）と難易度（やさしい・ふつう・むずかしい）を選べる

## 公開（GitHub Pages）

`.github/workflows/deploy.yml` が main への push のたびにテスト・ビルドして GitHub Pages に公開します。
無料プランではリポジトリを Public にする必要があります（Settings → Pages → Source を「GitHub Actions」に）。

## 開発

```
npm test          # ゲーム計算のテスト
npm run balance   # バランス確認用の試算
npm run build     # 公開用ビルド（dist/）
```

- `src/data/` 空港・機種・経済指標のデータ（数値は概算）
- `src/engine/` ゲームの計算（画面から独立）
- `src/ui/` 画面
